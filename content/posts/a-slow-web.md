前阵子重做了自己的个人站点。朋友们问得最多的问题是：为什么不用现成的主题？为什么不用框架？为什么页面加载完还要等一会儿，才让文字慢慢出现？

答案有点任性：因为我想做一个**慢慢加载**的网站。

不是技术上慢，而是感受上慢。

## 速度是一种价值观

我们习惯用毫秒衡量一个网站的好坏。首屏时间、可交互时间、跳出率，每一个数字都在提醒你：再快一点，用户随时会走。

这当然没错。工具应该高效，信息应该易得，等待是一种成本。但并非所有网页都承担着同样的任务。电商页面需要尽快让人找到商品，新闻站点需要抢在第一时间推送消息，而一个个人博客的任务，可能恰好相反。

它不需要你在三秒内完成什么。它只是希望你在某个下午，愿意花十分钟读一段不那么着急的文字。

> 一个好的个人网站，不应该像便利店，而应该像一间朋友的书房。门没锁，灯亮着，你可以进来坐一会儿。

## 从排版开始

我把大部分时间花在了排版上，而不是功能上。

正文的行高是 `1.95`，段间距大约是 `1.35em`，中文使用宋体作为标题、无衬线字体作为正文。标题的字距稍微收紧一点，正文的字距则保持宽松。链接下方有一条颜色很淡的线，鼠标移上去才会变深。

这些都是很小的决定，小到很难被明确地“看见”。但把它们叠在一起，就构成了阅读时的呼吸感。

```css
.prose {
  max-width: 68ch;
  font-size: 17px;
  line-height: 1.95;
  color: var(--ink-soft);
}

.prose h2 {
  margin: 2.4em 0 0.8em;
  font-family: var(--serif);
  font-weight: 500;
  letter-spacing: -0.025em;
}
```

有一个细节我反复调了很久：段落的颜色不能和标题一样深。正文如果太黑，阅读会变得紧张；如果太灰，又显得没有力气。最后我选了一种偏暖的深灰，像是在纸上写字，而不是在屏幕上喊话。

## 让出现有一点节奏

首页的元素会依次淡入，每一条延迟大概几十毫秒。文章卡片的图片在鼠标悬停时缓慢放大，速度是 `0.8s`，足够让人察觉到，但又不至于打断阅读。

这些动效没有实际功能。它们唯一的作用，是让页面看起来像是被慢慢展开，而不是一次性砸到眼前。

| 元素 | 时长 | 缓动 |
| --- | --- | --- |
| 首屏文字 | 800ms | cubic-bezier(0.2, 0.65, 0.3, 1) |
| 卡片浮现 | 750ms | 同上 |
| 图片缩放 | 800ms | 同上 |
| 主题切换 | 250ms | ease |

我刻意没有使用弹跳、旋转或者视差滚动。那些效果很热闹，但会抢走文字的主角位置。一个博客最重要的动效，应该是你的眼睛从一个句子移动到下一个句子。

## 慢，不等于没有效率

需要说明的是，这个网站本身并不“重”。

- 没有前端框架，页面是构建时生成的静态 HTML；
- CSS 和 JavaScript 都是手写的，没有引入任何第三方库；
- 图片使用 SVG 和 PNG，总大小控制在几百 KB；
- 没有字体文件请求，完全依赖系统字体；
- 全站可以离线阅读，除了搜索索引需要一次请求。

我所说的“慢”，是叙事上的从容，不是工程上的懒惰。**真正的克制，是在该快的地方快，在该慢的地方允许自己慢下来。**

## 最后

做完这个网站之后，我发现自己打开它的次数变多了。

以前那个用模板搭起来的站点，功能更全，加载更快，但我很少回去。现在这个版本甚至连评论都没有，却让我愿意在里面多待一会儿。

也许这就是个人网站的意义：它不需要赢过谁，只需要成为一个你愿意回去的地方。

> 网站会旧，技术会过时。但如果一个页面曾经让某个人安静地读完一段话，它就已经比很多“完美”的产品更接近目的。
